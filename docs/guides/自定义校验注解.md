# 自定义校验注解

## 核心机制

Spring Boot 的参数校验基于 JSR-380 规范。当内置注解（`@NotBlank`、`@Email`、`@Pattern` 等）无法满足业务需求时，可以通过 **自定义注解 + ConstraintValidator** 实现任意校验逻辑。

整体流程：

```
请求参数 → @Valid 触发校验 → 找到字段上的注解 → @Constraint 指向 Validator → isValid() 执行 → 失败则抛出 MethodArgumentNotValidException
```

## 两件套结构

每个自定义校验注解由两部分组成：

| 组件 | 职责 |
|------|------|
| **注解定义**（`@interface`） | 声明注解名称、默认错误信息、作用目标 |
| **校验器**（`ConstraintValidator`） | 实现具体校验逻辑 |

## 实战：从零写一个 @IdCard（身份证号校验）

### 第一步：定义注解

```java
package org.joint.common.annotation;

import jakarta.validation.Constraint;
import jakarta.validation.Payload;
import java.lang.annotation.*;

@Target({ElementType.FIELD, ElementType.PARAMETER})   // 可标注在字段和方法参数上
@Retention(RetentionPolicy.RUNTIME)                    // 运行时保留，校验框架才能读取
@Documented
@Constraint(validatedBy = IdCardValidator.class)       // 绑定校验器
public @interface IdCard {

    // 以下三个属性是 JSR-380 规范要求的固定模板

    String message() default "身份证号格式不正确";       // 校验失败时的错误信息

    Class<?>[] groups() default {};                     // 分组校验支持

    Class<? extends Payload>[] payload() default {};    // 元数据载荷（一般不用）
}
```

**三个固定属性说明：**

- `message` — 校验失败时返回的提示，使用时可覆盖：`@IdCard(message = "请输入正确的身份证")`
- `groups` — 配合 `@Validated(CreateGroup.class)` 实现分组校验
- `payload` — 规范要求，实际开发中极少使用

### 第二步：实现校验器

```java
package org.joint.common.annotation;

import jakarta.validation.ConstraintValidator;
import jakarta.validation.ConstraintValidatorContext;
import java.util.regex.Pattern;

public class IdCardValidator implements ConstraintValidator<IdCard, String> {
    //                                                    ↑注解类型  ↑被校验字段类型

    // 18位身份证号正则（简化版）
    private static final Pattern ID_CARD_PATTERN =
            Pattern.compile("^[1-9]\\d{5}(19|20)\\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\\d|3[01])\\d{3}[\\dXx]$");

    @Override
    public void initialize(IdCard annotation) {
        // 可选：读取注解上的自定义属性，用于初始化校验器
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null || value.isEmpty()) {
            return true;  // null 和空串交给 @NotBlank 处理，职责分离
        }
        return ID_CARD_PATTERN.matcher(value).matches();
    }
}
```

**关键设计：`null` 返回 `true`**

这是 JSR-380 的惯例。自定义注解只负责「格式对不对」，「能不能为空」由 `@NotBlank` / `@NotNull` 控制。这样两个注解可以自由组合：

```java
@NotBlank @IdCard          // 必填 + 格式校验
private String idCard;

@IdCard                     // 选填，填了就校验格式
private String idCard;
```

### 第三步：使用

```java
@Data
public class RealNameDto {

    @NotBlank(message = "姓名不能为空")
    private String name;

    @NotBlank(message = "身份证号不能为空")
    @IdCard
    private String idCard;

    @Phone  // 复用已有的手机号校验
    private String phone;
}
```

```java
@PostMapping("/verify")
public String verify(@Valid @RequestBody RealNameDto dto) {
    return "校验通过";
}
```

校验失败时（由 GlobalExceptionHandler 统一处理）：

```json
{
    "code": 400,
    "message": "身份证号格式不正确",
    "data": null
}
```

## 进阶：带参数的注解

注解可以携带自定义参数，让校验器更灵活。

### 示例：@EnumValue（枚举值校验）

校验字段值是否在指定的整数集合中：

```java
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Constraint(validatedBy = EnumValueValidator.class)
public @interface EnumValue {

    String message() default "值不在允许范围内";

    int[] values();  // 自定义参数：允许的值列表

    Class<?>[] groups() default {};

    Class<? extends Payload>[] payload() default {};
}
```

```java
public class EnumValueValidator implements ConstraintValidator<EnumValue, Integer> {

    private int[] allowedValues;

    @Override
    public void initialize(EnumValue annotation) {
        this.allowedValues = annotation.values();  // 读取注解参数
    }

    @Override
    public boolean isValid(Integer value, ConstraintValidatorContext context) {
        if (value == null) {
            return true;
        }
        for (int allowed : allowedValues) {
            if (value == allowed) {
                return true;
            }
        }
        return false;
    }
}
```

使用：

```java
@EnumValue(values = {0, 1}, message = "状态只能为 0 或 1")
private Integer status;

@EnumValue(values = {1, 2, 3}, message = "类型无效")
private Integer type;
```

## 模板速查

写自定义校验注解时，复制这个模板改两处即可：

```java
// 1. 注解 — 改名称和 message
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Constraint(validatedBy = XxxValidator.class)
public @interface Xxx {
    String message() default "校验失败提示";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

// 2. 校验器 — 改泛型和 isValid 逻辑
public class XxxValidator implements ConstraintValidator<Xxx, String> {
    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null) return true;
        // 校验逻辑
    }
}
```

## 与 Nexus 对照

| Nexus (class-validator) | Joint (Hibernate Validator) |
|---|---|
| 自定义装饰器 `registerDecorator()` | `@interface` + `ConstraintValidator` |
| `validate()` 函数 | `isValid()` 方法 |
| `ValidationArguments` | `ConstraintValidatorContext` |
| 装饰器参数 `constraints: [...]` | 注解属性 `int[] values()` |
